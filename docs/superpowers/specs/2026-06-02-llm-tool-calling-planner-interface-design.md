# LLM Tool-Calling Planner Interface Design

## Goal

Add a model-agnostic LLM/tool-calling planner interface without binding FireClaw to a specific provider or API.

## Scope

This phase does not call OpenAI, local LLMs, or network services. It adds typed planner context, a mockable client interface, validation, and rule-based fallback.

## Design

`PlannerContext` carries the extra information a future LLM planner needs:

- `session_id`
- `turn_index`
- recent session memory records
- skill metadata

`RuleBasedPlanner.plan()` accepts the context but can ignore it.

`LLMToolCallingPlanner` receives:

- a client object with `plan(request: dict) -> dict`;
- a fallback planner, defaulting to `RuleBasedPlanner`.

The planner sends the command and context to the client, then validates a structured response:

```json
{
  "status": "planned",
  "message": "Generated by planner.",
  "intent": "direct_skill_invocation",
  "target_floor": null,
  "steps": [
    {"skill_name": "echo_policy", "inputs": {"text": "二楼"}}
  ]
}
```

If the response is invalid, unsupported, or requests clarification, the result is converted into a normal `PlanningResult`. Malformed planned responses fall back to the rule-based planner.

## Agent Integration

`FireClawAgent` accepts an optional planner. It builds `PlannerContext` after resolving session context and before calling `planner.plan(...)`.

## Testing

Add tests for:

- LLM planner converts a valid structured response into `PlanningResult`;
- client request includes command, session id, turn index, recent records, and skill metadata;
- malformed planned response falls back to rule planner;
- agent can use an injected planner.

## Research Impact

This creates the boundary needed for future OpenClaw-style natural-language planning while keeping experiments reproducible with deterministic tests and mock clients.
